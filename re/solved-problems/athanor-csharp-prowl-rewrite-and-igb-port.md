# athanor-csharp-prowl-rewrite-and-igb-port

**Technique:** Byte-level format porting verified against real game files first, live GUI verification second, deep disassembly of the game's own DLLs (not the mismatched 2010 SDK build) only where arithmetic and testing ran out of runway

## Notes

## Context

"Athanor" is a modding toolkit for the Alchemy-engine X-Men Legends games (X-Men Legends II: Rise of Apocalypse primarily, with MUA1/MUA2 and a homebrew X-Men Legends 1 recompilation as stated long-term targets). It began as a Rust/Tauri app; partway through, the project was deliberately discarded and rebuilt from scratch in C# on top of [Prowl](https://github.com/ProwlEngine/Prowl), an open-source MIT-licensed 3D engine, so the end goal could be a real "play in editor" 3D game engine editor rather than a standalone format-editing utility. `docs/FEATURES.md` and `docs/FORMATS.md` (the accumulated format knowledge) were explicitly preserved across that rewrite per direct instruction - they are the spec the new C# code implements against, not a claim of what's implemented yet.

An accidental `rm -rf .git` mid-rewrite destroyed the local Rust-era git history (a flawed bash safety-guard executed its own destructive branch unconditionally). Recovered by using copies of the docs/features/format-sample files that had already been saved elsewhere as an unrelated earlier precaution, and by re-initializing git fresh on the Prowl baseline. Disclosed in full to the user immediately; they explicitly accepted moving forward since the format knowledge was intact.

## What shipped this session, verified

**XMLB** (`Athanor.Alchemy/Xmlb.cs`): the Alchemy engine's binary UI-widget-tree container (also used for package manifests, conversations, character placement, nav data, buoy data - one format under six extensions). Full byte-level spec (magic `0x000011B1`, node layout, deduplicated string table, sibling-chain top level) documented as its own pattern entry (`xmlb-ui-format`). Round-tripped byte-identical against all 5,883 real files across a retail install. Wired into a real running Prowl editor: import → browse as a tree → edit node/attributes → Save rebuilds and overwrites the source file, confirmed live against `options.XMLB`'s actual 104 nodes.

**IGB** (`Athanor.Alchemy/Igb.cs`, `IgbImage.cs`): Alchemy's model/texture/scene container, the bulk of a retail install (4,886 files) and a genuine object-system serialisation (every file carries its own class schema). Full structural spec (header, meta-field table, class table with its field-descriptor-interleaving gotcha, object directory) documented as `igb-model-scene-format`. Parses 4,885 of 4,886 real files (the one failure confirmed as a genuinely truncated shipped file, not a parser bug - the class table's last name is cut off mid-string at the exact 4,096-byte file boundary). Texture location and DXT1/3/5 + RGBA8888 decode wired directly into the editor as a native `Texture2D` importer - `.igb` files that resolve to an `igImage` import as textures with zero custom asset-type plumbing (the same pipeline every other texture format uses gets thumbnails, material slots, and the inspector for free); files that don't resolve to an image (models, scenes) are skipped, not failed.

**Model geometry decode is the open remainder.** The shared-entry-buffer arithmetic (locating the extra memory region beyond what the object directory declares) is confirmed and ported, matching the retail install's own numbers exactly on the two files the original investigation checked by hand. Turning that region into actual vertex/index arrays needed a much deeper disassembly push (see `igb-model-scene-format`'s third technique entry) that reached a well-defined but still-open state: the generic per-field read dispatch is now understood for scalars, strings, and MemoryRef fields, but not yet for ObjectRef or Compound fields, and the field iteration order within an object is still an educated guess.

## Process notes worth keeping

- **Rigor bar, held consistently**: every format claim in this session was checked against real retail files, not asserted from documentation or intuition alone - including two "does the arithmetic land exactly" schema-prediction experiments that came back negative and were reported as negative (ruling out a hypothesis is progress; a wrong hypothesis reported as confirmed is not).
- **Two Echo/Prowl-specific gotchas hit and fixed live** (not caught by unit tests alone): Prowl's serializer (`Echo`) is opt-in per field via `[SerializeField]` on private fields, not reflection over everything public - a plain public property silently vanished on the very first asset-cache round-trip in the real editor. And a custom asset editor's tree widget rendered with width 0 until measured via a one-frame-delayed probe box, the same pattern an existing `AudioMixerAssetEditor` in Prowl already used.
- **The game's own DLLs, not the SDK's**: `libIGCore_xml2.dll`/`libIGGfx_xml2.dll` (staged in the RE lab share) disagree with the 2010 Alchemy SDK build on several points already caught mid-investigation (the write path in particular). Reversing against the SDK build alone would have produced confidently wrong conclusions in at least two places this session.
- **Live GUI verification caught real bugs unit tests couldn't**: PowerShell + user32.dll P/Invoke window automation (foreground, click, screenshot a real running editor process) surfaced both Prowl gotchas above. In a later, differently-sandboxed environment this same technique produced zero effect despite every precondition (correct window, correct cursor position, even `SendInput`) checking out - worth noting as an environment-dependent technique, not a universally reliable one.
