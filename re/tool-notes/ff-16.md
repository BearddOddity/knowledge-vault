# ff-16

## FF-16 (Find Frequent 16-bit) — https://github.com/HexLasso/…

FF-16 (Find Frequent 16-bit) — https://github.com/HexLasso/FF-16

A static tool that finds frequently occurring 16-bit patterns across a whole
file, to locate repeated structures and infer layout. Tunable block size, gap
range and frequency threshold, plus filters to exclude zero-heavy or
bit-imbalanced patterns.

Why it is worth keeping for this project
----------------------------------------
It is the COMPLEMENT to ImHex's Pattern Language, not a duplicate. ImHex needs a
hypothesis first: read the writer in a decompiler, then express the struct.
FF-16 needs no hypothesis — it finds record boundaries and stride from
repetition alone.

The sharpest use here is NOT the IGB model format, it is mining .data/.rdata for
vtables and descriptor tables. On 2026-09-04 a session searched .rdata by hand
for a function address, found two vtables holding it at slot +0x10
(0x003EEC00 and 0x003EED08), and only then discovered the object actually in use
carried a third vtable at 0x003EECB0 with a different layout. A stride and
record size derived mechanically from the data would have shown the family of
tables in one pass.

It also gives evidence INDEPENDENT of Ghidra's naming, which matters here:
1,282 of 3,890 vfuncN names in this project are recorded as misattributed, so a
layout inferred from the bytes is a useful cross-check rather than another
opinion from the same source.

Limit, stated plainly: it finds structure in DATA. It says nothing about control
flow. It can enumerate which vtables exist and how large they are; it cannot say
why the wrong one was installed on an object.

Usage: ff-16 <file> [-bpc blocks-per-chunk] [-m min-gaps] [-g max-gaps]
[-t freq-threshold] [-z zero-filter] [-bb bit-balance-filter]
