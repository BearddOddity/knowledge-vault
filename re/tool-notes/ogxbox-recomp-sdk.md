# ogxbox-recomp-sdk

## The build automation's plain build()/build(reconfigure=True…

The build automation's plain build()/build(reconfigure=True) only re-runs the ALREADY-COMPILED recompiler tool (ogxbox.exe) against a title's config - it never recompiles that tool from its own C source. Editing the recompiler's own generator source (src/writers.c, src/emit.c, etc.) has zero effect on any title's output until the tool binary itself is rebuilt separately: its own CMake+ninja build lives at the repo root, and needs the MSVC dev environment loaded first (a bare shell cannot find clang-cl/kernel32.lib) - `cmd /c '"<VS install>\VC\Auxiliary\Build\vcvars64.bat" && cd /d "<repo>\build" && ninja'`. Only after that manual rebuild does the title's own build(reconfigure=True) actually pick up a generator-level fix. Silently editing writers.c/emit.c and re-testing without this step will look like the fix "didn't work" when really it was never compiled in at all - always grep the freshly reconfigured generated output for the expected new code shape (e.g. a new function call or literal the fix should have introduced) to confirm the tool rebuild actually took effect before spending time debugging a fix that never ran.
